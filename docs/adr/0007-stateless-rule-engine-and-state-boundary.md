# ADR 0007: 탐지 룰 엔진의 무상태성(Stateless) 보장 및 분산 세션 상태 관리 경계 분리

- **상태**: 승인됨 (Accepted)
- **결정자**: 클라우드 A (테크 리드 @mmmphyun), 보안 (@gkacksdnjs22-stack)
- **일자**: 2026-09-09
- **소유 직무**: 클라우드 A (아키텍처 거버넌스), 보안 (룰 엔진)
- **관련 PR / Issue**: PR #13, Issue #21

## 1. 배경 및 문제 제기 (Context)

- PR #13(SSH 단일 계정 무차별 대입 1차 탐지 룰 구현) 코드 리뷰 과정에서 다음 기술적 문제가 제기됨:
  - **현상**: AWS CloudWatch Logs Subscription Filter는 실시간 로그 전달 시 5초 동안 발생한 5건의 실패 이벤트를 3건과 2건 등 여러 번의 Lambda 호출 배치(Batch)로 분할 전달할 수 있음.
  - **결함**: `evaluate_rules(logs)`가 현재 호출에 인입된 단일 배치만 검사할 경우, 분할된 각 배치가 임계치(5회)에 미달하여 브루트포스 공격을 탐지하지 못함 (미탐지 취약점).
  - **초기 반응**: 보안 룰 엔진 내부에 외부 상태 저장소(DynamoDB 등)를 직접 연동해야 한다는 요구가 발생하여, 단위 기능 PR이 인프라 작업(Issue #21)에 블로킹되는 작업 병목(Deadlock)이 형성됨.

## 2. 대안 검토 및 트레이드오프 분석 (Considered Options)

| 구분 | 방안 1: 룰 엔진 내부 상태 연동 | 방안 2: 오케스트레이터 분산 상태 관리 (채택) | 방안 3: CloudWatch 메트릭 필터 활용 |
| :--- | :--- | :--- | :--- |
| **구조** | `rules.py` 내부에서 DynamoDB Boto3 직접 호출 | `rules.py`는 순수 함수 유지, Lambda 진입점에서 상태 취합 후 전달 | Lambda 호출 전 CW 메트릭 필터로 5분 집계 후 임계치 도달 시 1회 트리거 |
| **장점** | 호출부 변경 없이 룰 엔진 단독 해결 | **단위 테스트 격리 완벽 유지**, 룰 엔진 복잡도 0, 재사용성 극대화 | DynamoDB 구축 비용/지연 없음, 완전한 서버리스 네이티브 |
| **단점** | 룰 엔진 단위 테스트에 Moto/AWS 의존성 강제, R&R 침범 | 오케스트레이터의 런타임 상태 관리 책임 증가 | 원문 로그 페이로드 전달 시 추가 파이프라인 구성 필요 |

---

## 3. 아키텍처 결정 (Decision)

1. **탐지 룰 엔진의 순수 함수(Stateless) 원칙 확립**:
   - `src/detection/rules.py`의 `evaluate_rules`는 외부 I/O나 상태 저장을 일체 수행하지 않는 **결정론적 순수 함수(Deterministic Pure Function)**로 책임을 엄격히 한정함.
   - 단일 배치 내에서의 5분 슬라이딩 윈도우 및 룰 우선순위 검증(Brute Force 우선)으로 PR #13의 기능 요구사항을 완결함.
2. **배치 간 세션 상태 관리의 오케스트레이터(클라우드 A) 이관**:
   - Lambda 배치 경계를 넘어선 5분 윈도우 로그 누적은 **보안 룰 엔진의 책임이 아니라 클라우드 A(오케스트레이터 및 인프라)**의 고유 책임으로 정의함.
   - 본 과제는 Issue #21로 분리하여 **Phase 2 (1차 E2E 데모 파이프라인 완성 후)** 인프라 레벨에서 구현함.

---

## 4. 기대 효과 및 결과 (Consequences)

- **긍정적 영향**:
  - 보안 담당자의 PR #13 블로킹 즉시 해제 및 E2E 마일스톤 정상화.
  - 룰 엔진의 빠른 테스트 속도 유지 (외부 Mock 불필요, 수 밀리초 내 실행).
  - 분산 이벤트 스트리밍 환경에서 관심사의 분리(Separation of Concerns) 모범 사례 확립.
- **관리 대상 한계점 (Technical Debt)**:
  - Phase 1 데모 단계에서는 단일 배치 인입 시나리오(수 초 내 집중 공격)에 한해 10초 관통 대응을 보장함.
  - 분할 인입 대응은 Phase 2(Issue #21) 구현 전까지 미탐지 한계점으로 인지 및 문서화함.
