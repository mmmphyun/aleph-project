# ADR 0008: AI 에이전트 PR 스태킹 방지를 위한 WIP 1개 제한 및 인-PR(In-PR) 커밋 거버넌스

- **상태**: 승인됨 (Accepted)
- **결정자**: 클라우드 A (테크 리드 @mmmphyun)
- **일자**: 2026-09-09
- **소유 직무**: 클라우드 A (플랫폼 거버넌스 및 하네스)
- **관련 PR / Issue**: PR #13, PR #23, PR #24, Issue #21, Issue #22

---

## 1. 배경 및 문제 제기 (Context)

- PR #13(SSH 무차별 대입 1차 탐지 룰 구현)이 코드 리뷰(Changes requested)로 인해 `main`에 머지되지 않고 대기 상태에 놓임.
- **에이전트의 과잉 문제해결(Overzealous Task Completion) 및 유휴 회피 행동**:
  - 보안 에이전트는 선행 PR의 머지를 대기(Idle)하지 않고, 노션 칸반 보드에서 후속 티켓을 가져와 Issue #22를 오픈함.
  - 다음 작업(오탐 방어 테스트)을 동작시키기 위해 13번 PR의 코드가 필수적이라는 이유로, `main`이 아닌 **미머지 브랜치(`feat/security-rules-engine`)를 부모(Base)로 삼아 `feat/security-noisy-log-tests` 브랜치를 분기하고 PR #23을 생성(PR Stacking)**함.
- **결과적 붕괴 메커니즘**:
  - 테크 리드가 선행 PR #13을 검토 후 Squash Merge하고 원격 브랜치를 삭제하자, **부모 브랜치가 사라진 자식 PR #23이 GitHub 정책에 의해 자동 강제 종료(Closed)**되어 작업이 공중에 붕 뜨는 브랜치 연쇄 파괴 사고가 발생함.
  - 또한 리뷰 피드백을 반영할 때마다 새 이슈(#21, #22)를 계속 따면서 이슈 트래커와 칸반 보드가 급격히 파편화됨.

## 2. 대안 검토 및 트레이드오프 분석 (Considered Options)

| 구분 | 방안 1: 프롬프트 줄글 가이드 강화 | 방안 2: Git Pre-push 훅 검사 | 방안 3: 스크립트 WIP 하드 가드 + In-PR 규칙 (채택) |
| :--- | :--- | :--- | :--- |
| **차단 시점** | 작업 착수 단계 (자연어) | Git 푸시 시점 (로컬) | **작업 착수 단계 (`get_my_tasks.js`)** |
| **강제력** | **매우 낮음** (에이전트가 쉽게 우회/무시) | 중간 (로컬 환경 설정 의존) | **절대적** (`process.exit(1)`로 프로세스 강제 종료) |
| **정보 차단** | 노션 URL이 노출되어 이슈 생성 가능 | 이미 이슈/브랜치가 생성된 후 차단 | **노션 티켓 목록 자체를 은폐하여 입력 원천 봉쇄** |

## 3. 아키텍처 결정 (Decision)

1. **`scripts/get_my_tasks.js` WIP 1개 제한 물리적 하드 가드 구현**:
   - 노션 DB 조회 전 `gh pr list --state open`을 실행하여 현재 직무(`.agent-role`)의 미머지 PR(`feat/<role>-*`, `fix/<role>-*`)을 사전 검사함.
   - 열린 PR이 1건이라도 존재할 경우:
     - 상세 경고 메시지 출력 후 **종료 코드 1(`process.exit(1)`)로 스크립트를 즉시 강제 셧다운**함.
     - 노션 카드 링크 출력을 원천 차단하여 에이전트가 `gh issue create`를 실행할 수 있는 입력 데이터를 제거함.
2. **`AGENTS.md` 인-PR(In-PR) 커밋 거버넌스 확립**:
   - **새 이슈 생성 절대 금지 (In-PR Fix)**: PR 리뷰에서 들어온 버그 수정, 룰 보완, 테스트 추가는 절대로 새 이슈를 따지 않고 동일 PR 브랜치에서 추가 커밋(`fix: ...`, `test: ...`)으로 반영하도록 강제함.
   - **PR 스태킹 전면 금지**: 본인 직무의 선행 PR이 `main`에 머지되기 전에는 어떠한 후속 티켓도 착수할 수 없음.
   - **Follow-up Issue 분리 기준**: 현재 PR 스코프를 완전히 벗어나 타 직무 아키텍처 변경이 수반되는 경우에 한해 테크 리드 승인 후 1건만 분리 등록.

## 4. 기대 효과 및 결과 (Consequences)

- **긍정적 영향**:
  - 미머지 브랜치 위에 후속 작업을 얹는 PR 스태킹 및 브랜치 연쇄 파괴 사고 원천 차단.
  - 리뷰 피드백 수정 시 불필요한 이슈 증식(Issue Inflation)을 방지하고 단일 PR의 응집도 유지.
  - AI 에이전트 개발 환경에서 "자연어 프롬프트의 한계"를 인정하고 "스크립트 레벨 물리적 제어"로 발전시킨 거버넌스 성숙도 증빙.
- **관리 대상 한계점**:
  - 긴급 핫픽스나 다중 작업이 불가피할 경우를 대비하여 `ALLOW_CONCURRENT_WIP=1` 환경변수 우회 경로를 보존함.
