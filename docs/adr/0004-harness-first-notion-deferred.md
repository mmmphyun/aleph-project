# ADR 0004: 개발 병목 차단을 위한 선(先) 하네스 배포, 후(後) 노션 연동

- **상태**: 승인됨 (Accepted)
- **결정자**: 클라우드 A (테크 리드 @mmmphyun)
- **일자**: 2026-09-05
- **소유 직무**: 클라우드 A (거버넌스/DX)

---

## 1. 배경 및 문제 제기 (Context)

- 프로젝트 초기 4명의 팀원이 동시에 작업을 착수해야 하는 상황에서, 외부 협업 도구(노션 칸반 보드 API) 연동 및 권한 설정 문제가 발생함.
- 만약 노션 API 키 발급 및 양방향 동기화 스크립트 구축이 완료될 때까지 팀원들의 개발 착수를 차단(Blocking)할 경우:
  - 1~2일 차의 핵심 엔지니어링 골든타임이 문서/도구 세팅으로 인해 허비됨.
  - 외부 API 의존성으로 인해 로컬 개발 및 단위 테스트 환경 조성이 지연됨.

---

## 2. 대안 검토 및 트레이드오프 분석 (Considered Options)

| 구분 | 방안 1: 도구 완비 후 착수 (노션 선행) | 방안 2: 선(先) 하네스 배포, 후(後) 노션 연동 (채택) |
| :--- | :--- | :--- |
| **팀원 착수 속도** | 노션 세팅 완료까지 전원 대기 (심각한 병목) | **Day 1~2에 즉시 로컬 개발 착수 가능** |
| **초기 자산 집중** | 협업 툴 배관 구축에 시간 소모 | **데이터 계약(Contracts) 및 Mock 테스트베드 선구축에 집중** |
| **외부 장애 영향** | 노션 API 장애/권한 오류 시 전체 워크플로우 마비 | GitHub Issues/PR을 기본으로 운영하고 노션은 단방향 연동으로 장애 격리 |

---

## 3. 아키텍처 결정 (Decision)

- **선(先) 테스트베드/하네스 배포, 후(後) 노션 자동화 연동 결정**:
  1. **Day 1~2 (개발 하네스 우선 배포)**:
     - `src/contracts/` (Pydantic V2 불변 인터페이스 계약 2종) 확정.
     - `tests/mock_data/` 및 `tests/conftest.py` 모의 테스트베드 선배포.
     - 팀원 4명이 즉시 독립 브랜치에서 단위 테스트를 작성하며 병렬 개발 착수하도록 조치.
  2. **Day 3 (노션 비동기 배관 구축)**:
     - GitHub Actions 단방향(One-way) 워크플로우를 구성하여 PR 상태 변경 시 노션 칸반 보드를 백그라운드 업데이트하도록 격리 연동.
     - 노션 API 장애가 팀원들의 로컬 개발 및 CI/CD 머지를 방해하지 않도록 Fallback(이슈 수동 URL 기재) 정책 명문화.

---

## 4. 기대 효과 및 결과 (Consequences)

- **긍정적 영향**:
  - 외부 도구 종속성으로 인한 프로젝트 초반 병목 완전 해소.
  - 팀원 전원이 첫 주차에 본인 도메인의 단위 테스트 및 핵심 모듈 구현을 완결함.
- **관리 대상 한계점**:
  - 팀원들이 작업 착수 시 GitHub Issue 본문에 노션 URL을 복사하여 연결하는 최소한의 수동 절차 안내 필요.
