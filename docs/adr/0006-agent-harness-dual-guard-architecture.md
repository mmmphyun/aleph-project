# ADR 0006: 에이전트 협업 거버넌스를 위한 소프트 가드와 하드 가드의 이원화 및 감사 투명성 설계

- **상태**: 승인됨 (Accepted)
- **결정자**: 클라우드 A (테크 리드 @mmmphyun)
- **일자**: 2026-09-09
- **소유 직무**: 클라우드 A (플랫폼 거버넌스 및 CI/CD)
- **관련 PR / Issue**: PR #15, PR #16, PR #17, PR #20, Issue #19

---

## 1. 배경 및 문제 제기 (Context)

- 팀원들이 코딩 에이전트(Codex, Cursor, Claude Code)를 활용하여 본격 개발에 착수함에 따라, 헌법 문서(`AGENTS.md`) 및 온보딩 가이드 중심의 **소프트 가드(Soft Guard)**가 가진 한계와 휴먼/에이전트 결함이 연속적으로 노출됨:
  1. **메타데이터 파편화**: 노션 API 미설정 시 에이전트가 이슈 생성을 건너뛰어 PR 본문에 노션 URL과 이슈 번호가 누락됨 (PR #15, #17).
  2. **수집 경로 이탈**: 에이전트가 타 직무 침범을 회피하려다 `network/tests/`처럼 규격 외 경로에 테스트를 작성하여 기본 CI 수집에서 누락됨 (PR #15).
  3. **환경 충돌 및 우회 편법**: 로컬 상위 폴더 `.gitignore` 문법 오류 발생 시, 에이전트가 근본 원인을 해결하는 대신 `--no-respect-gitignore` 플래그로 린트를 우회함 (PR #15).
  4. **과거 베이스 분기**: 작업 착수 전 `git pull origin main`을 생략하여 방금 머지된 거버넌스를 인지하지 못한 채 브랜치를 생성함 (PR #17).
- "규칙을 문서에 적어두면 사람이 읽고 에이전트에게 시킬 것이다"라는 가정이 무너지면서, **시스템 레벨에서 위반을 물리적으로 차단하는 하드 가드(Hard Guard)**의 도입 필요성이 대두됨.

## 2. 대안 검토 및 트레이드오프 분석 (Considered Options)

| 구분 | 방안 1: 순수 소프트 가드 강화 | 방안 2: 전방위 극단적 하드 가드 | 방안 3: 이원화 설계 및 감사 투명성 보존 (채택) |
| :--- | :--- | :--- | :--- |
| **구조** | 프롬프트와 문서만 더 길고 자세하게 보강 | 모든 규칙(우회 플래그 텍스트, 본문 키워드 등)을 CI 스크립트로 전면 차단 | 구조적 파편화는 CI로 물리 차단하되, 우회 텍스트 차단은 의도적 배제 |
| **장점** | CI 워크플로우 수정 비용 없음 | 규정 위반 PR의 완전 차단 | **파이프라인 무결성 100% 확보** + **솔직한 디버깅 증적(Audit Trail) 보존** |
| **단점** | 에이전트 프롬프트 무시 및 재발 방어 불가 | **작업자가 우회 사실 자체를 본문에서 숨기게 만듦 (블라인드 위험)** | CI 검증 스텝 증가 및 정적 린터 유지보수 비용 발생 |

---

## 3. 아키텍처 결정 (Decision)

1. **물리적 하드 가드(Hard Guard) 3종 구축**:
   - **PR 본문 메타데이터 CI 검증 (`.github/workflows/pr_title_lint.yml`)**:
     - 직무 기능 PR(`feat/fix`) 작성 시 PR 본문에 유효한 노션 카드 URL과 사전 발행된 GitHub Issue 번호(`#\d+`)가 누락되면 `exit 1`로 CI를 실패 처리하여 머지 버튼을 물리 차단함.
   - **테스트 파일 표준 경로 정적 검사 (`.github/workflows/ci.yml`, `scripts/check.ps1`)**:
     - `tests/` 및 `tests/unit/` 외부에 임의 생성된 `test_*.py`가 존재하면 CI 및 로컬 `check.ps1`에서 즉시 중단함.
   - **PR 머지 시 연관 GitHub Issue 자동 종결 (`.github/workflows/notion_sync.yml`)**:
     - PR이 머지될 때 본문의 `#이슈번호`를 파싱하여 GitHub API로 해당 이슈를 `completed` 상태로 자동 Close하고 감사 코멘트를 남김.
2. **의도적 하드 가드 배제 (레드팀 감사 투명성 원칙)**:
   - PR 본문 내 우회 플래그(`--no-respect-gitignore`) 작성 탐지 차단은 **"작업자가 린트 우회 사실 자체를 지우고 감추게 만든다"**는 심각한 부작용(Inspection Blindness)이 확인되어 의도적으로 하드 가드에서 배제함.
   - 우회 여부는 PR 본문에 솔직히 남기도록 하고, 1:1 동료 리뷰어 및 테크 리드가 코드 리뷰 단계에서 식별하여 시정하도록 이원화함.
3. **소프트 가드(Soft Guard) 재정립**:
   - 5단계 표준 라이프사이클(`main 동기화 -> 이슈 선발행 -> 브랜치 분기 -> check.ps1 -> PR 및 리뷰어 지정`)을 `AGENTS.md`에 명문화.
   - 에이전트 코드 리뷰 시 사소한 트집(Nit-pick)과 장황한 줄글을 억제하기 위해 `[P1 - 필수]`/`[P2 - 권장]` 2단계 태그 분류 및 최대 2개 불릿 제한의 초경량 리뷰 표준 확립.

## 4. 기대 효과 및 결과 (Consequences)

- **긍정적 영향**:
  - 노션 카드 미연동, 이슈 미발행, 테스트 경로 이탈 등 반복되던 휴먼/에이전트 실수의 원천 차단.
  - 작업자가 겪은 로컬 실행 오류나 우회 로그가 은폐되지 않고 투명하게 노출되어 빠른 문제 해결 가능.
  - AI 에이전트 도입 환경에서 "자동화로 강제할 영역(경로/인터페이스)"과 "사람의 감시로 둘 영역(의도/동작)"의 명확한 엔지니어링 기준 수립.
- **관리 대상 한계점 (Operational Risk)**:
  - PR 본문 정규식 검증으로 인해 단순 오타나 서식 불일치 시 CI가 실패할 수 있음. 이는 `.github/pull_request_template.md` 자동 로딩 메커니즘을 배포하여 입력 실수를 사전에 예방함.
