## 1. 담당 도메인 개요 및 네트워크 R&R

네트워크 도메인은 CloudShield 파이프라인의 실효성을 입증하기 위한 **모의 침투 공격 시뮬레이션(Hydra/Nmap/Curl), 매초 신규 TCP 3-Way Handshake 계측기 개발, Wireshark/tcpdump L4 패킷 플래그 분석, 제어 평면 API 성공과 데이터 평면 패킷 드롭의 전파 지연 간극 실측 규명, L4/L7 방어 수단의 상호 보완성 도출**을 전담했습니다.

단순 콘솔 상태나 세션 유지 여부로 차단을 판정하지 않고, 패킷 단위의 물리적 인바운드 드롭 시점을 직접 계측하여 분산 환경의 현실적 한계를 증빙했습니다.

## 2. 핵심 엔지니어링 딥다이브 (패킷 분석 & 전파 지연 실측)

### 2.1 매초 신규 TCP 연결을 시도하는 능동 계측기 개발
* **배경 및 관측 결함 배제**:
  - 기존에 이미 맺어져 있는 SSH 세션의 생존 여부로 차단을 판정할 경우, 세션 유지 시간 및 TCP FIN/RST 처리 지연으로 인해 정확한 인프라 방화벽 차단 시점을 입증할 수 없습니다.
  - 이를 해결하기 위해 매초 독립적인 포트에서 타깃 EC2로 새로운 TCP 3-Way Handshake를 시도하는 **능동 패킷 계측기(`ec2_hydra_measurement.py`)**를 자체 개발했습니다.
* **공격 환경 격리**:
  - 별도의 공격 노드(`ATTACKER_PUBLIC_IP`)에서 Hydra 9.2 기반의 패스워드 무차별 대입 공격 및 웹 비인가 디렉터리 경로 스캔을 수행하고 동시에 tcpdump로 공격자 관점의 송수신 패킷을 전수 캡처했습니다.

### 2.2 Wireshark/tcpdump L4 TCP 패킷 플래그 정밀 분석
* **정상 구간 vs 차단 구간의 패킷 상태 전이 규명**:
  - **정상 구간**: 클라이언트 SYN $\rightarrow$ 타깃 서버 SYN-ACK $\rightarrow$ 클라이언트 ACK의 정상 3단계 연결 수립 및 SSH 버전 배너 교환을 확인했습니다.
  - **차단 구간**: L4 격리 보안 그룹(`quarantine_sg`)이 적용된 직후, 클라이언트가 발송한 **36개 연속 신규 SYN 패킷에 대해 타깃 서버가 아무런 응답을 주지 않고(Silent Drop, 무응답) 타임아웃**되는 흐름을 패킷 레벨에서 입증했습니다.
  - 서버 RST 패킷에 의한 명시적 종료가 아니라, 스테이트풀 보안 그룹의 인바운드 룰 제거로 인한 무응답 패킷 드롭임을 명확히 판정했습니다.

### 2.3 제어 평면 API 성공과 데이터 평면 패킷 차단의 전파 지연 간극 실측
* **문제 발견 (Plane Confusion 해소)**:
  - Lambda 오케스트레이터의 WAF 차단 API(Boto3 `update_ip_set`) 호출은 **1.40초** 만에 종료되어 Slack 알림이 발송되었으나, 실제 데이터 평면의 웹 공격 트래픽은 이후에도 수 초간 HTTP 200/404로 통신이 유지되는 현상을 식별했습니다.
* **원인 규명**:
  - API 반환 완료(제어 평면)와 AWS WAF의 리전 배포망에 IPSet 차단 정책이 물리적으로 전파되어 실제 패킷을 차단하는 시점(데이터 평면) 간에 **물리적 전파 지연**이 존재함을 패킷으로 규명했습니다.
  - 이를 통해 "차단 API 호출 성공 = 트래픽 즉시 차단"이라는 인과관계의 비약을 배제하고 엄격한 관측 팩트를 수립했습니다.

### 2.4 L4 SG vs L7 WAF 계층별 트레이드오프 및 솔직한 한계 공유
* **실측 지표 대조**:
  - **L4 Security Group**: 서버 5회 실패 기록 후 **5.48초 만에 첫 무응답 SYN** 관측 (타임아웃 확인: 6.28초). 인스턴스 전면의 신규 연결을 즉각 차단하지만 정상 서비스에 영향을 미칠 수 있는 광범위 격리 특성을 가집니다.
  - **L7 AWS WAF**: 공격자 IP만을 정밀하게 차단하지만 Lambda 시작부터 첫 403 응답까지 **18.20초**(공격 첫 SYN 기준 **21.29초**)가 소요되어 초기 목표치(10초)에는 미달함을 솔직하게 공유했습니다.
* **상호 보완성 및 가용성 부수 효과 방어**:
  - L4 SG 격리는 인스턴스 전체 포트를 차단하므로 공격자의 유도 공격 시 정상 사용자 통신까지 중단되는 가용성 부수 효과가 따릅니다.
  - 따라서 대민 서비스는 공격자 IP만 선별 차단하는 L7 WAF를 1차 방어선으로 두고, L4 SG는 호스트 침해 시 인스턴스를 즉각 분리하는 최후의 비상 차단으로 역할을 분리하여 상호 보완하도록 설계했습니다.
