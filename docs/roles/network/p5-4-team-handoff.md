## 1. 이미 받은 정보와 준비 결과

| 항목 | 현재 상태 |
| --- | --- |
| 대상·권한 | 로컬 승인 프로필의 STS 신원, 타깃 주소·Baseline SG, WAF 잔류 차단 부재 확인. EC2 복구 DryRunOperation |
| 공격 노드 | 승인 키로 ubuntu 접속, IMDS 신원 일치. 별도 Python 3.12.16과 기존 네트워크 자산 8개 해시 대조 |
| Grafana | localhost 인증 사용. 기존 B 대시보드 5개 쿼리 모두 실제 AWS 조회 Complete, 익명 대시보드 401 |
| 통합 실행 | 로컬 컨트롤러에서 기존 공격 도구 → 실제 사건 조회 → A의 기존 복구 함수 → 독립 TCP/HTTP 확인 → B의 3차 카드 → 증거 회수/기존 타임라인 분석 연결 |
| 자격증명 | AWS 키·Slack 웹훅은 로컬에만 보존. 공격 노드로 전달하지 않음 |
| SSH 키 인증 | TCP 복구 모드에서는 선택 해제. 타깃 공개키 등록을 기다리지 않고 준비 가능. 카드의 인증 DoD는 미확인 |
| 실제 실행 | 공격·타깃 탐침·캡처·복구·Slack 전송 모두 미실행. 유효한 실행 승인 파일은 아직 없음 |

AWS 키·복구 호출 규격·공격 노드 키·ALB 주소·Slack 웹훅은 이미 받았으므로 다시 요청하지 않는다. WAF 쓰기 권한은 소유자가 승인했지만 실제 Update로 시험하지 않았다. Grafana의 직접 인증에는 별도 AssumeRole/GetFederationToken이 필요하지 않다.

## 2. A에게 전달할 내용

> 로컬 컨트롤러와 Grafana AWS 연결 준비를 마쳤고, TCP/HTTP 모드의 실제 preflight blockers가 0개입니다. 전달하신 기존 SG 복구 함수와 WAF 단일 IP 해제 함수를 그대로 호출하도록 연결했습니다. 전체 IPSet 해제·IAM 변경·새 복구 엔진은 없습니다. 아직 공격하거나 복구 API를 실제 실행하지 않았습니다.
>
> 최종 실측 시 현재 Lambda 함수 버전/코드 해시와 기준 커밋 대응, 공격 출발지 허용 및 탐지 윈도우 잔존 여부를 확인해 주세요. 동일 출발지의 다른 시험은 겹치지 않게 하고, 실행 가능한 시간대와 비상 대응 담당자를 공유해 주세요. 기존 러너 규격의 승인자·승인/만료 시각·대상·출발지가 담긴 유한 승인 파일을 확정한 뒤 한 번씩 실행하겠습니다.

현재 단일 컨트롤러가 승인된 복구를 호출하므로 A가 별도 복구 스크립트를 새로 작성할 필요는 없다. 실제 사건 ID를 확인하지 못하면 임의 사건이나 simulate_lambda_threat 실행으로 대체하지 않으며 3차 카드를 보내지 않는다. 공격 요청 후 장애가 나면 승인된 대상 복구를 시도하고 실패를 보존한다.

## 3. B에게 전달할 내용

> Grafana의 기존 cloudshield-cloudwatch 데이터소스와 P5-2 대시보드 5개 쿼리를 직접 인증으로 연결했고 모두 Complete를 확인했습니다. 웹훅도 로컬에 설정했으며 테스트 메시지는 보내지 않았습니다. 실제 실행의 사건 ID를 유지해 기존 3차 카드 함수를 호출하도록 준비했습니다.
>
> 실측 시 cloudshield_test의 인증 실패 및 Nginx 로그 수집·구독 정상성을 확인해 주세요. 같은 사건의 WAF BLOCK/ALLOW 원문, Slack 1·2·3차 카드 원문/원본 ts, Grafana 화면을 해당 실행 시간 구간으로 보존해 주세요. 컨트롤러는 패널 쿼리 응답을 보존하지만 Incoming Webhook 응답만으로 원본 Slack ts를 얻을 수 없습니다.

타깃의 SSH 공개키 등록은 TCP 복구 데모 진행 조건으로 요청하지 않는다. 전체 P5 카드의 키 인증 회복까지 증명하려는 경우에만 별도 승인 계정·공개키 등록·허용 명령 true·검증된 호스트 키를 요청한다. 개인키는 전달하지 않는다.

## 4. 실측과 카드 완료를 구분할 사항

SSH 1회 후 정상 복구·잔류 상태를 확인하고 Web 1회를 실행한다. 부분 실패 시 자동 재공격하지 않는다. 연속 캡처는 최대 120초·2,000패킷이며 조기 종료를 성공으로 처리하지 않는다.

TCP 연결 성공은 키 인증 성공을 뜻하지 않는다. 루트 HEAD 200은 WAF BLOCK 원문이나 동일 연결 재사용 증거를 대신하지 않는다. 첫 실제 공격 패킷·시계 최대 오차·Slack 원본 ts가 없으면 해당 값과 10초 SLA는 미확인으로 남긴다. 기존 B 패널의 탐지→API 반환 지연도 물리적 차단 SLA로 바꾸어 부르지 않는다.
