## 2. 클라우드 A에게 전달할 요청문

> P5-4 네트워크 실행 환경과 dry-run 준비를 마쳤습니다. 실제 공격은 아직 시작하지 않았습니다. 아래 현재 배포·허용·복구 근거와 실행 가능한 시간대를 전달 부탁드립니다. 새 모의 로그 주입 사건을 만들어 복구하지 않고, 실제 트래픽으로 생성된 같은 incident_id를 유지해야 합니다.

| 필요한 확인/자료 | 필요한 내용 |
| --- | --- |
| 현재 대상·배포 확인 | 이미 전달된 타깃의 AWS 계정·VPC·공인 IP 대응, Baseline/Quarantine SG 및 WAF 연결. 실제 함수 이름·버전/별칭·LastModified·CodeSha256과 저장소 커밋 대응 |
| 출발지·정상성 | 이미 전달된 공격 IP의 TCP 22 허용, WAF 차단 잔존 여부, SG 기준 상태. 지난 사건·윈도우가 다음 실측을 오염시키지 않는지 확인 |
| 복구 담당자·시간 | 실제 동시 대기 담당자와 시간대. 관측 한도 120초 안에서 공격 종료 후 복구 시작 T0+85초·구성 확인 +105초 가능 여부. 불가능하면 공격 전에 관측 계획 재조정 |
| 실제 사건 복구 경로 | 기존 승인된 복구 진입점/담당자 절차. 실제 incident_id·원본 IncidentReport를 유지해 L4 SG·L7 WAF 복구 및 3차 카드에 전달하는 방법. 네트워크가 API를 대신 호출하지 않음 |
| 복구 원본 | 요청·실제 시작·API 응답·구성 재조회 각각의 UTC 원문/해상도·요청 ID·SG 목록·IPSet 결과·계층별 성공/실패·원본 파일 해시. 멱등성 재실행은 별도 승인 범위에서만 제공 |
| 실행 승인 파일 | 현재 출발지·타깃·승인자·승인/만료 시각을 확인한 기존 러너 규격. 최대 24시간/16KiB·실행 사용자 소유/0600 유지. 비밀번호·토큰은 포함하지 않음 |

`simulate_lambda_threat.py`를 다시 실행한 별도 사건을 이번 복구 증거로 사용하지 않는다. 실제 사건용 기존 절차가 없다면 그 사실과 필요한 A 영역 조치를 알려준다. 네트워크 측에서 새 복구 실행기를 만들지 않는다.

## 3. 클라우드 B에게 전달할 요청문

> 같은 P5-4 실측 시간에 수집·Grafana·Slack 관측을 부탁드립니다. 기존 P5-2 고정 로그 사건이나 P5-3 보고서로 이번 왕복을 대체하지 않습니다. 현재 인증 가능한 관제 환경 또는 아래 원본 제공 경로를 알려주세요. AWS 키·Slack 토큰을 채팅이나 Git에 붙여넣을 필요는 없습니다.

| 필요한 확인/자료 | 필요한 내용 |
| --- | --- |
| 전용 계정·수집 | cloudshield_test의 현재 상태, Failed password 수집·CW Agent/구독 정상성, 실제 auth/nginx/WAF 로그 그룹·스트림. 키 인증 회복을 확인할 별도 계정·승인된 키 경로·호스트 지문·허용 명령 |
| AWS/Grafana 조회 | 현재 사용할 읽기 전용 로그인/프로필의 실제 호스트 또는 인증된 Grafana 주소. 네트워크 측 로컬 Grafana는 준비됐지만 AWS 자격증명을 연결하지 않은 상태 |
| 같은 사건 CW 원본 | incident_id·출발지/대상·시간 구간을 연결하는 원문. timestamp/ingestionTime/eventId·로그 스트림과 원본 좌표, ThreatRemediatedMetric의 pipeline_timestamps·duration_seconds·remediation_success |
| WAF 원본 | 실제 요청의 BLOCK/ALLOW·규칙·요청 식별자·메서드·URI·원문 시각. 루트 403과 별도 대조하며 스캔 경로 응답을 정상 탐침 회복으로 합치지 않음 |
| 패널 대조 | 기존 p5-2.json의 5개 쿼리와 같은 조회 범위·분 경계, Complete 상태·queryId·행 수·집계값·필터. Grafana 데이터소스 응답·화면 캡처를 같은 구간으로 제공 |
| Slack 원본 | 같은 incident_id의 1·2·3차 카드 원문·원본 ts·실제 게시 순서·조회 범위. 2차 enhanced/Fallback 상태를 연결하고 수동 재전송으로 순서를 맞추지 않음 |

공격 노드에 AWS 키를 추가할 필요는 없다. A/B가 승인된 환경에서 조회한 원본을 비공개 경로로 제공해도 된다. 이 경우 조회 주체·호스트·명령/쿼리·범위·상태·해시·선별 이력을 보존하고, 네트워크의 직접 AWS 조회와 구분한다. Grafana 실제 대조에는 인증된 데이터 조회 환경이 별도로 필요하다.

## 4. 실측 시작 전에 함께 확정할 사항

1. SSH 1회 후 A 복구·정상성·잔존 상태를 확인한 뒤 Web 1회를 별도 run_id로 실행한다. 실패 회차는 보존하고 자동 재공격하지 않는다.
2. 120초·2,000패킷 연속 캡처와 기존 내부 상한을 유지한다. 대상·출발지 불일치, baseline/캡처/저장 실패, 시간 초과 시 중단한다.
3. 현재 실제 B 패널은 후보 인입·탐지→API 반환·LLM 상태·사건 타임라인이다. 별도 L4/L7·LLM·복구 지연 패널이 있다는 전제로 DoD를 판정하지 않는다.
4. Web 연결 재사용의 유한 관측 방법, SSH 키 인증 회복 경로, 시계 오차 측정 범위를 확정한다. 현재 curl은 --rate 옵션을 지원하지 않으며 기존 HEAD 탐침은 연결 재사용을 보장하지 않는다.
5. 원본은 Git 밖에 보존하고, 공개 자료는 식별자 마스킹·좌표·원본/공개 해시를 분리한다. 미확보 구간은 null과 사유로 남긴다.
