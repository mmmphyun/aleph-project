# CloudShield 거버넌스 개정 계획: 분산 인프라 비기능 제약 검증 룰(5대 Pre-flight Gate)

* **작성 일자**: 2026-10-07
* **작성자**: 클라우드 A (테크 리드 @mmmphyun)
* **목적**: PR #135의 다중 분산 결함(상태성 누락, 복제 지연, 400KB 포화, 순서 역전, 무음 실패) 재발 방지를 위한 사전 구현 아키텍처 점검 게이트 수립

---

## 1. 개정 배경 및 원인 분석

* **현상**: Nginx Web L7 오케스트레이터 및 슬라이딩 윈도우 구현 시, 비즈니스 로직 자체는 정상이었으나 분산 시스템 환경의 물리적 제약(AWS 하드 리밋, 비동기 스트림 지연, 서버리스 실패 전파 규격)을 사전에 점검하지 않아 6차례에 걸친 리뷰 피드백 루프가 발생함.
* **근본 원인**: 기존 거버넌스가 '기능 구현'과 '로컬 단위 테스트 통과'에만 집중되어 있어, AWS 리소스 사용 시 수반되는 물리적 제약을 구현 전에 자가 검증하는 시스템적 게이트가 부재했음.

## 2. 거버넌스 헌법(AGENTS.md) 반영 명세 (PR #135 머지 후 즉시 반영)

### 2.1 [AGENTS.md] 제4.1조 신설: 분산 인프라 5대 사전 점검 게이트 (Distributed Pre-flight Gate)
클라우드 리소스(Lambda, DynamoDB, WAF, SQS, CloudWatch Agent 등)를 다루는 모듈 설계 및 코드 작성 시, 에이전트는 코드 작성 전 아래 5대 물리적 제약을 역산하여 설계 브리핑에 명시해야 함:
1. **런타임 수명주기 및 상태성 (Runtime Lifecycle)**:
   - Lambda 무상태(Stateless) 환경에서의 호출 간 상태 공유 필요성 및 인메모리 휘발성 결함 차단.
2. **스토리지 물리적 상한선 (Storage Boundary)**:
   - DB/스토리지 단일 레코드 하드 리밋(DynamoDB 400KB 등) 확인, 무한 List append 방지(시간 버킷팅/슬롯 청킹/TTL).
3. **데이터 일관성 모델 (Consistency Model)**:
   - 쓰기 직후 후속 런타임의 즉시 읽기 요구조건 여부 및 Strongly Consistent Read 강제 필요성.
4. **비동기 스트림 순서 역전 (Out-of-Order Delivery)**:
   - 네트워크/버퍼링 지연으로 지연된 과거 이벤트(T1)가 미래 이벤트(T2)보다 늦게 도착했을 때 시간창 집계 무결성 보장(유효 구간 전수 평가).
5. **장애 격리 및 에러 전파 (Failure Escalation)**:
   - 무음 실패(Silent Failure) 차단. 상위 재시도 및 DLQ 트리거를 위한 명시적 함수 예외(`raise`) 전파 규격 준수.

### 2.2 [AGENTS.md] 제5.1조 보완: 카오스 테스트(Chaos Test) 작성 의무
- 분산 상태/윈도우링 모듈 구현 시 아래 회귀 테스트 동봉 의무화:
  - 역순/지연 배치 인입 검증 (Out-of-order Batch Test)
  - 스토리지 부분 장애 및 읽기/쓰기 실패 검증 (Partial Storage Failure Test)
  - 용량 상한선 포화 및 슬롯 전환 검증 (Storage Saturation Test)
