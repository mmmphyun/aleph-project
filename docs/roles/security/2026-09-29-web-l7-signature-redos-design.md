# Web L7 시그니처 및 ReDoS 방어 설계

- 담당: 보안 (`@gkacksdnjs22-stack`)
- Issue: [#98](https://github.com/mmmphyun/aleph-project/issues/98)
- Notion: [프로젝트 일정 티켓](https://notion.so/3e904d37c2258161a606ea1031436dcf)
- 연계: [네트워크 PR #90](https://github.com/mmmphyun/aleph-project/pull/90)

## 1. 목적과 범위

Nginx 접근 로그에서 Web 디렉터리 열거와 민감 파일 탐색을 식별하고 `BLOCK_WAF`를 요청한다. IP는 사람의 신원이나 최초 위치가 아니라 서버에서 관측한 출구로 취급한다.

- 보안: 공격 모델, 시그니처, 오탐 억제, ReDoS 방어 및 차단 요청 기준
- 네트워크: Gobuster/Curl 모의 공격과 패킷 검증
- 클라우드 B: Nginx 로그 포맷과 CloudWatch 수집
- 클라우드 A: WAF IPSet, Terraform 및 차단 오케스트레이터 구현

## 2. 공격 모델

네트워크 PR #90은 Curl 또는 Gobuster로 `admin`, `login`, `backup`, `config`, `private`, `debug`, `metrics` 등 합성 경로 1~20개를 조회한다. Curl 동시성은 1, Gobuster 동시성은 1~4다.

현재 도구는 숫자형 loopback 주소만 허용하므로 로컬 탐지 검증용이며, AWS VPC·WAF 관통 실측으로 간주하지 않는다.

확장 탐지 대상은 다음과 같다.

| 분류 | 예시 | 판정 원칙 |
|---|---|---|
| 민감 설정 | `/.env`, `/.git/config`, `/wp-config.php` | 높은 위험 신호 |
| 백업 파일 | `*.bak`, `*.sql`, `*.zip` | 높은 위험 신호 |
| 관리·진단 | `/admin`, `/debug`, `/metrics` | 반복성 확인 필요 |
| 정상 후보 | `/health`, `/robots.txt`, 정적 자원 | 단독 차단 금지 |

## 3. 탐지 기준

분석 필드는 요청 시각, `$remote_addr`, HTTP 메서드, 경로, 상태 코드, User-Agent와 요청 시간이다. `X-Forwarded-For`는 위조 가능하므로 신뢰 프록시가 확정되기 전에는 출발지 근거로 사용하지 않는다.

| 수준 | 초기 기준 | 조치 |
|---|---|---|
| 관찰 | 의심 경로 1~2개 또는 단발성 `/admin` | 로그 보존 |
| 경고 | 짧은 시간 안에 서로 다른 의심 경로 3개 이상과 실패 응답 반복 | 알림, 자동 차단 보류 |
| 차단 후보 | 10초 안에 서로 다른 의심 경로 5개 이상이며 3개 이상이 401·403·404 | `BLOCK_WAF` 요청 후보 |
| 고위험 후보 | 민감 파일 탐색과 추가 경로 열거가 함께 발생 | `BLOCK_WAF` 요청 후보 |

`10초·5개·실패 3개`는 프로젝트의 10초 목표와 PR #90의 최소 검증 실행에서 도출한 초기값이다. 정상 브라우저 요청과 Curl/Gobuster 로그를 비교한 뒤 확정한다.

현재 CloudWatch 구독 필터는 `401`, `403`, `404`만 Lambda로 전달한다. 따라서 경로 수는 전달된 실패 응답 안에서 계산한다. `200`, `301`, `302`까지 분석하려면 클라우드 B와 필터 범위 및 비용을 먼저 합의한다.

## 4. 시그니처와 ReDoS 방어

URL을 최대 두 번 디코딩한 뒤 경로와 쿼리를 분리하여 필요한 부분만 검사한다. 기존 `normalize_url_value`의 4,096자 제한을 유지한다.

```regex
^/(?:\.env|\.git(?:/config)?|wp-config\.php)$
^/(?:admin|debug|metrics|internal)(?:/|$)
\.(?:bak|sql|zip)(?:$|\?)
```

- 중첩 수량자, 역참조, 가변 길이 후방 탐색과 무제한 `.*`를 금지한다.
- 고정 경로는 정확 일치 집합을 우선 사용한다.
- 정규식은 앵커와 제한된 문자 클래스로 구성한다.
- 패턴별 목표 복잡도는 입력 길이 `n`에 대해 `O(n)`이다.
- 정상·공격·최대 길이·반복 문자 입력으로 선형 처리 여부를 회귀 검증한다.

## 5. WAF 차단 후 로그 상관분석

WAF 차단은 현재 출구 IP의 HTTP·HTTPS 경로를 막는 초동 대응이다. VPN·프록시·Tor 출구가 바뀌면 새 IP로 재접속할 수 있으며, 공유 IP 차단은 정상 사용자에게 영향을 줄 수 있다.

차단 후에는 외부 시스템에 역접속하지 않고 내부 로그만 연결한다.

```text
Nginx: 탐지 시각·출구 IP·요청 경로
CloudWatch: 수집 시각·로그 스트림·이벤트 ID
WAF: 차단 시각·규칙·IPSet 반영 결과
VPC Flow Logs: 출발지·목적지·포트·허용/거부
```

- 탐지부터 WAF 반영까지 10초 이내인지 확인한다.
- 차단 전 동일 IP가 요청한 경로와 순서를 확인한다.
- 다른 IP에서 유사한 경로 집합과 요청 특성이 반복되는지 비교한다.
- 여러 IP의 유사성은 `동일 공격자`가 아니라 `동일 공격 캠페인 후보`로 기록한다.

VPC Flow Logs에는 URL과 HTTP 헤더가 없으므로 연결 확인에만 사용한다. WAF 로그를 사용하려면 클라우드 A가 Web ACL 로깅과 보존 위치를 별도로 구성해야 한다. 기존 `IncidentReport` 계약에는 필드를 임의로 추가하지 않는다.

## 6. 검증 항목

| 표본 | 기대 결과 |
|---|---|
| Curl 후보 5개, 실패 3개 이상 | 차단 후보 |
| Gobuster 후보 5개, 동시성 1~4 | 순서와 무관하게 경로 다양성 탐지 |
| `/admin` 단발 요청 | 비차단 |
| `robots.txt`와 정적 자원 | 비차단 |
| 단일·이중 인코딩 민감 경로 | 정규화 후 동일 시그니처 적용 |
| 4,096자 반복 입력 | 제한 시간 안에 처리 |
| 4,096자 초과 입력 | 정규화 단계에서 거부 |

## 7. 결론

Web L7 공격은 IP 하나만으로 판정하지 않고 경로 위험도, 경로 다양성, 실패 응답과 시간적 반복성을 결합한다. 정규식은 제한된 입력과 선형 패턴으로 구성한다. WAF 차단 후에는 Nginx·CloudWatch·WAF·VPC Flow Logs를 시간축으로 상관분석하되 실제 신원 추적이나 해킹백으로 확대하지 않는다.
