## 2. 원본 사고 계약과 보강 경계

공통 계약 `contracts.incident.IncidentReport`의 `extra="forbid"`와 불변 객체 설정을
그대로 사용한다. 별도 사고 모델이나 위험도·액션 enum을 정의하지 않는다.

| 필드 | 응답 반영 정책 |
| --- | --- |
| `summary_ko` | 검증을 통과한 응답 문자열로 보강 가능, 최대 2,000자 |
| `recommendations` | 검증을 통과한 문자열 목록으로 보강 가능, 최대 10개·항목당 500자 |
| `incident_id`, `attack_type`, `mitre_id`, `risk_level` | 원본 값 강제 보존 |
| `source_ip`, `target_identifier`, `target_accounts`, `action_required` | 원본 값 강제 보존 |

모델이 대응 액션이나 출발지 주소를 바꾸어 출력하더라도, 결과의 해당 필드는
`base_report`에서 가져온다. 응답에 담긴 보호 필드의 값은 타입이나 IP·액션 형식의
유효성과 관계없이 폐기하고, 모델이 제안한 보호 필드 값을 검증 대상으로 승격하지 않는다.
보강 문장을 근거로 기존 탐지 판정·MITRE 매핑·위험도·차단
정책을 갱신하지 않는다. 원본 데이터와 허용한 두 보강 필드를 결합한 결과는
`IncidentReport`로 다시 검증한다. 기존 객체에 대한 필드 대입은 수행하지 않는다.

## 3. 프롬프트와 비신뢰 로그 처리

프롬프트에는 공통 `IncidentReport` JSON 스키마, 보강 목적과 보존 필드 규칙,
SSH 및 Web 사례의 few-shot 예시, 현재 기준 보고서와 제한된 로그를 포함한다.
응답은 설명·추가 키 없이 JSON으로 작성하도록 지시한다.

| 예시 계열 | 분석의 근거 | 기존 정책의 보존 |
| --- | --- | --- |
| SSH 무차별 대입 | 동일 IP·`cloudshield_test` 계정의 인증 실패 원문 5개를 요약하고, 성공 인증·실제 격리 여부는 미확인으로 구분 | `SSH Brute Force`, `T1110.001`, `HIGH`, `BLOCK_AND_QUARANTINE` 유지 |
| Web 디렉터리 스캔 | `/admin`·`/backup`·`/config`의 401·404·403과 `/debug`·`/metrics`의 200 등 5개 원문을 분석하고 WAF 집행·실제 노출 여부는 미확인으로 구분 | `Web Directory Scanning`, `T1595.003`, `HIGH`, `BLOCK_WAF` 유지 |

이 예시는 출력 형식과 필드 보존을 설명하기 위한 합성 입력이다. 새로운 공격 분류를
생성하거나 실제 운영 탐지 성능을 평가한 데이터로 사용하지 않는다.
예시 보고서는 기존 `map_threat_to_incident`로 생성해 탐지 계층의 기존 매핑과 일치시킨다.
각 예시의 출력은 입력 보고서를 그대로 복제하지 않고, 원문 로그에서 확인한 계정·경로·응답
근거로 `summary_ko`와 `recommendations`를 각각 보강한다. 나머지 모든 필드는 입력과
동일하게 유지한다. 출력은 공통 계약으로 재검증하고 실제 응답 파서도 통과해야 한다.

원문 로그와 보고서의 문자열 필드는 비신뢰 증거 데이터로 다룬다. 로그 안의 명령, 역할 선언,
JSON 출력 요구, 이전 지시 무시 문장은 분석 대상 증거로 취급하도록 명시하고,
상위 지시와 구분된 `ANALYSIS_INPUT_JSON` 객체에 넣는다. 문자열은 JSON으로 이스케이프해
경계 텍스트나 제어문자가 증거 안에 있어도 입력 JSON을 구성한다. 텍스트 경계와 지시문만으로 프롬프트 인젝션 방지
성능을 보장한다고 주장하지 않는다. 응답 파서의 보존 정책이 필드 변경 범위를 제한한다.

| 데이터 | 상한 및 처리 원칙 |
| --- | --- |
| 로그 | 문자열 목록의 첫 50개 로그, 로그당 4,096자, 합계 UTF-8 32,768바이트 이내로 제한 |
| 원본 보고서 JSON | UTF-8 16,384바이트 이내. JSON을 중간에서 잘라 계약을 훼손하지 않음 |
| 전체 프롬프트 | JSON 이스케이프·스키마·few-shot 예시를 포함해 UTF-8 262,144바이트 이내 |
| 모델 응답 | UTF-8 32,768바이트 이내. 상한 초과 응답은 파싱 성공으로 취급하지 않음 |
| 응답 서두 | 공백 정리 후 최대 1,024자, 구조를 혼동시키는 중괄호·대괄호·백틱은 불허 |
| 보강 요약 | 공백만 있는 값은 불허, 문자열 최대 2,000자 |
| 보강 권고 | 문자열 배열 최대 10개, 각 최대 500자·공백만 있는 항목은 불허. 빈 배열은 허용 |

문자 수와 UTF-8 바이트 수는 서로 다른 제한이다. 한글·다중 바이트 문자를 포함해
바이트 상한을 적용하고 문자 중간에서 잘린 바이트는 결과 문자열에 남기지 않는다.
`raw_logs`는 문자열 목록이며 목록의 원소 하나를 로그 한 줄로 취급한다.
상한 뒤의 원소는 분석하지 않고, `truncation`에 전체·포함·생략·절단 수를 따로 담는다.
로그 절단은 증거 일부를 생략할 수 있다. 요약이 전체 원문을
분석했다는 의미로 확대되지 않도록 호출자는 제공한 증거 범위를 함께 관리해야 한다.
이 제한은 애플리케이션 입력 제한이며 Bedrock 모델의 토큰 제한이나 과금 상한을
실측한 값이 아니다.

보고서 및 전체 프롬프트 크기 초과와 잘못된 호출 인자는 `TypeError` 또는 `ValueError`로
호출부에 전파한다. 선택된 입력 로그와 보고서 문자열의 잘못된 UTF-8 표현은
`UnicodeError`로 전파하며, 대체 문자로 조용히 바꾸지 않는다.

## 4. 응답 수용과 실패 처리

응답의 의미 있는 페이로드는 단일 JSON 객체여야 한다. `summary_ko`·`recommendations`
두 보강 키는 필수이고, 나머지는 공통 계약에 존재하는 보호 필드만 허용한다.
보호 필드는 일부 또는 전체가 있어도 값을 버린다. 따라서 전체 `IncidentReport` 객체와
보강 두 필드만 있는 객체를 모두 지원한다. 계약 밖의 필드는 허용하지 않는다.
단일 JSON 코드 펜스 또는 짧은 서두 뒤의 단일 객체를 추출할 수 있지만,
느슨한 텍스트 검색으로 여러 후보 중 하나를 임의 선택하지 않는다.

| 응답 형태 또는 결함 | 처리 |
| --- | --- |
| 허용한 객체의 엄격 JSON | 필드·용량 검증 후 원본 기반 보고서로 결합 |
| 단일 JSON 펜스 또는 짧은 서두 | 추출 후 동일한 JSON·계약 검증 적용 |
| 여러 JSON 객체·객체 후보 | 모호한 응답으로 거부 |
| 중복 키 | JSON 디코딩 단계에서 거부 |
| `NaN`, `Infinity` 등 비표준 상수 | 엄격 JSON 위반으로 거부 |
| 배열·스칼라·필수 보강 필드 누락·추가 키 | 허용 객체 형태 위반으로 거부 |
| 잘못된 보강 필드 타입·요약/권고 상한 초과 | 보강 계약 위반으로 거부. 보호 필드의 응답 값은 사용하지 않음 |
| UTF-8로 인코딩할 수 없는 원시 응답 또는 보강 문자열 | lone surrogate 등 잘못된 출력을 거부 |
| 응답 바이트 상한 초과·잘린 JSON·파싱 불가 | 분석 보강 실패로 처리 |

보강 문자열을 숫자에서 문자열로 바꾸는 타입 강제 변환은 하지 않는다.
한국어 2~3문장 작성은 프롬프트 지시이며 파서는 언어와 문장 수를 판별하지 않는다.

응답을 해석하거나 검증하지 못하면 `base_report`와 **동일한 객체**를 반환한다.
기본값을 채운 새 사고 보고서를 만들거나, 일부만 유효한 응답을 부분 반영하지 않는다.
내용을 포함하지 않는 고정 경고를 남겨 보강 실패를 식별한다. 원문 로그, 모델 응답,
보고서 필드 및 파싱 예외에 포함될 수 있는 응답 조각은 경고에 기록하지 않는다.
경고는 외부 알림·AWS 쓰기와 구분되는 로컬 로깅 부수효과다.
`base_report` 자체가 `IncidentReport`가 아닌 호출부 타입 오류는 원본 반환으로
숨기지 않고 `TypeError`로 전파한다.

## 5. 분산 인프라 제약 검토

| 제약 | 이번 범위의 결정 |
| --- | --- |
| 런타임 수명주기·상태성 | 두 함수는 입력으로만 결과를 구성한다. 호출 간 집계·캐시·전역 가변 상태를 도입하지 않음 |
| 스토리지 상한 | 새 DB와 무한 append를 도입하지 않음. 보고서·로그·응답에 별도 크기 상한 적용 |
| 일관성 모델 | 저장소 쓰기 후 읽기 경로가 없어 Strongly Consistent Read가 필요하지 않음 |
| 순서 역전 | 시계열 윈도우를 새로 만들거나 재판정하지 않음. 기존 결정론적 판정과 입력 보고서를 기준으로 유지 |
| 장애 전파 | 응답 형식·검증 실패만 경고와 원본 반환으로 격리. 실제 AWS/네트워크 장애 전파·재시도·DLQ 정책은 후속 호출부에서 별도로 설계 |

보강 실패의 원본 반환은 이번 파서에 명시한 계약이다. DynamoDB·Bedrock·차단 API 등
시스템 장애를 조용히 삼켜도 된다는 플랫폼 공통 예외 정책으로 확대하지 않는다.

## 6. 검증 결과

`powershell .\scripts\check.ps1` 원본 게이트가 리뷰 반영 후 **1157 passed, 4 skipped**로 통과했다
(211.23초, 종료 코드 0). R&R 경계선·테스트 경로·Ruff 린트·포맷 검사도 통과했다.
건너뛴 4건은 기존 Terraform 도구·provider 환경 미준비에 따른 선택적 검증이며,
새 테스트에는 skip을 추가하지 않았다. 기존 소켓 차단 smoke 테스트의 경고 1건이 있다.
실제 LLM 응답, Bedrock 모델 호출, 프롬프트 인젝션 저항성,
운영 정확도·지연·비용은 이번 오프라인 검증으로 입증하지 않았다.

단위 테스트는 보안 소유 경로 `tests/unit/test_llm_analyzer.py`에서 합성 입력으로
82개를 수행했다. 프롬프트의 스키마·SSH/Web 예시·비신뢰 로그 경계와 크기 제한, 정상 JSON·펜스·서두
추출, 원본 필드 강제 보존, 추가 키·중복 키·비표준 상수·잘못된 타입·다중 객체·상한 초과
거부, 실패 시 객체 동일성과 내용 없는 경고를 확인했다.
리뷰의 [Few-shot 보강 권고](https://github.com/mmmphyun/aleph-project/pull/202#pullrequestreview-5568947256)에
대해 SSH/Web 예시에서 두 보강 필드의 실제 변경·원문 근거·나머지 필드 보존·파서 왕복을
검증하는 회귀 2개를 추가했다. 기존 예시에서 두 테스트가 실패하고 수정 후 통과함을 확인했다.
두 사례의 합성 원문 각각 5개는 기존 계약 파서와 탐지 룰에서도 해당 시그니처로 판정됐다.

기존 사용자 수정과 `assets/`를 보존하기 위해 최신 main에서 분리한 작업 공간에서 실행했다.
Windows 부모·자식 인코딩 일치를 위해 `PYTHONUTF8=1`, `PYTHONIOENCODING=utf-8`을 설정했고,
검증 스크립트·제약·의존성 정의는 변경하지 않았다. 다른 직무의 런타임·수집·알림·인프라,
보호된 공통 계약과 의존성은 이번 작업의 수정 범위에 포함하지 않는다.
