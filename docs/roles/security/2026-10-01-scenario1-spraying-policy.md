# 시나리오 1 Password Spraying 정책 정렬

- Issue: #110
- Notion: https://notion.so/3eb04d37c2258004b82cead6d9b8b095
- 연계 PR: #92, #114

## 보안 정책과 입력 계약

`SSH_PASSWORD_SPRAYING`은 `T1110.003 / MEDIUM / BLOCK_IP_ONLY`로 유지한다.
`SSH_BRUTE_FORCE`는 기존 `T1110.001 / HIGH / BLOCK_AND_QUARANTINE`을 유지한다.
보안 매퍼는 원문 분석 및 누적 윈도우 판정 모두의 사고 정책을 생성한다.

`target_accounts`는 리스트 또는 튜플 등 문자열 시퀀스를 받아 순서대로 중복을 제거한다.
입력 목록은 변경하지 않으며 문자열 자체, 빈 계정 및 문자열이 아닌 원소는 거부한다.
누적 윈도우에서 탐지된 계정 전체를 수집하는 책임은 호출부에 있다.

## 플랫폼 연계 한계

PR #114는 오케스트레이터의 중복 정책을 제거하고 보안 매퍼 호출을 연결했다.
현재 호출은 `(username,)`만 전달하므로 여러 배치의 누적 대상 계정 전체는 아직 보고되지 않는다.
단일 계정 입력 거부는 현재 호출 계약을 깨므로 적용하지 않는다.
클라우드 A가 누적 계정 조회·전달을 연결해야 계정 다양성 증거가 보고서에 완전히 보존된다.

현재 `BLOCK_IP_ONLY` 집행은 WAF IPSet을 사용한다. WAF는 HTTP/HTTPS를 검사하므로
SSH 차단 성공을 입증하지 못한다. 권고 문구는 출발지 `/32`의 SSH 네트워크 차단으로
정렬하지만 실제 L4 차단 구현과 성공 판정은 클라우드 A·네트워크 담당의 후속 범위다.
이번 변경은 차단 API를 실행하거나 새로운 차단 액션을 정의하지 않는다.
