## 3. SSH·Web 전문과 원문 대조

전문은 앞서 연결한 두 content-review JSON에 보존한다. 다음은 실제 페이지에서 읽은
요약이며, 서명·임시 토큰이 포함된 URL은 저장하지 않았다.

### SSH: INC-1793331935-0051

```text
[1. 침해 개요]
출발지 IP 198.51.100.51에서 단일 계정 대상 SSH 비밀번호 추측 공격이 감지되었습니다. 대상 계정은 cloudshield_test이며 MITRE ATT&CK T1110.001으로 분류됩니다.

[2. 관측 로그 근거]
Oct 14 09:40:01~05에 cloudshield_test 계정으로 Failed password 로그 5건이 관측됐습니다. 성공 인증 로그는 제공되지 않았습니다.

[3. 영향도 및 침해 판정]
성공 인증·실제 EC2 격리 결과는 미확인으로 원본 매퍼 판정을 유지합니다. 영향 범위는 제공된 실패 표본으로 한정합니다.
```

권고는 `[즉시 조치]` 인접 성공 인증·세션 대조, `[설정 점검]` TCP 차단·격리 집행 증거와
정상 관리 접속 영향 확인, `[재발 방지]` 권한·인증 정책 검토 및 재발 관측 순서다.
원문은 `invalid user cloudshield_test`의 실패 5건이다. 사용자 제공 CloudWatch 인용은
처음 2줄과 총 5건 설명이며, 나머지 3줄은 HTML에 있는 원문으로 대조했다.
제공되지 않은 CloudWatch 3줄을 독립 수집한 것처럼 기록하지 않는다.
SSH 원문에 연도·시간대가 없으므로 보고서 생성일로 보정하지 않는다.

### Web: INC-1793337609-0088

```text
[1. 침해 개요]
출발지 IP 198.51.100.88의 Web 경로 열거가 관측됐습니다. 제공된 표본은 서로 다른 경로 5개입니다.

[2. 관측 로그 근거]
30/Oct/2026:05:20:07에 5개 경로 중 /admin·/backup·/config 응답은 401·404·403입니다. /debug·/metrics는 200으로 응답했습니다.

[3. 영향도 및 침해 판정]
200만으로 민감 자원 노출을, 403만으로 WAF 집행을 확정할 수 없어 원본 매퍼 판정을 유지합니다. 응답 본문과 WAF 집행 근거는 미확인입니다.
```

사용자 제공 CloudWatch Nginx 원문 5줄은 HTML 수집 로그와 모두 일치한다.
모든 요청의 시각은 `30/Oct/2026:05:20:07 +0000`, 출발지는 `198.51.100.88`이다.

| URI | HTTP 상태 | 응답 바이트 | 요약 대조 |
| --- | --- | --- | --- |
| /admin | 401 | 150 | 일치 |
| /backup | 404 | 153 | 일치 |
| /config | 403 | 162 | 일치 |
| /debug | 200 | 2048 | 일치 |
| /metrics | 200 | 4096 | 일치 |

응답 바이트를 모델 토큰 수와 혼동하지 않는다. 200을 민감 정보 노출로, 403을 WAF 집행으로
단정하지 않았고 응답 본문·집행 근거를 미확인으로 구분했다.
권고는 URI·시각·IP를 WAF ALLOW/BLOCK 원문과 대조한 뒤, 진단 경로의 응답 본문·접근 정책과
정상 사용자 영향을 점검하고 불필요한 경로 정리·승인된 재검증을 수행하는 순서다.

| 대조 필드 | SSH | Web |
| --- | --- | --- |
| 사고 ID | INC-1793331935-0051 | INC-1793337609-0088 |
| 출발지 IP | 198.51.100.51 | 198.51.100.88 |
| 화면 MITRE ID | T1110.001 | T1595.003 |
| 대상 EC2 | i-0605f8529598ed820 | i-0605f8529598ed820 |
| 현재 매퍼의 기대 액션 | BLOCK_AND_QUARANTINE | BLOCK_WAF |
| 3단 분석 문장 수 | 2/2/2 | 2/2/2 |
| 엄격 파서 수용 | 수용 | 수용 |

파서 검수는 화면에서 읽은 분석 두 필드와 가시 식별자로 재구성한 매퍼 보고서를 사용했다.
생성된 계약의 보호 필드가 재구성한 원본과 같음을 확인했다. 실제 운영 1차·2차 JSON 전체를
수신해 action_required까지 독립 대조한 것으로 표현하지 않는다. HTML의 차단 완료 표 역시
그 자체로 실제 집행 성공을 독립 증명하지 않는다.

## 5. 보안 구현과 고정 평가셋

LLM은 summary_ko·recommendations만 출력하고 앱이 원본 보호 필드를 보존한 전체
IncidentReport를 다시 검증한다. 이전 전체 JSON 응답도 지원하며, 엄격 경로에서 모델이
제공한 보호 필드가 원본과 다르면 전체 응답을 거부한다. 공통 계약은 변경하지 않았다.

정상 종료는 end_turn을 유지한다. max_tokens의 완전해 보이는 JSON, stop_sequence,
도구·필터·미지 종료값은 임의 수용하지 않는다. 종료 사유·유효 정수 사용량은 본문 없이
`cloudshield.bedrock_response`에 기록하며 사건 결과는 기존 `cloudshield.llm_analysis`만 집계한다.
예상 LLM 장애는 원본으로 격리하고 보안 어댑터의 입력 오류·예상 밖 프로그래밍 오류는 전파한다.

[golden-set.json](evidence/p5-3-2026-10-30/golden-set.json)은 합성 SSH 5건·Web 5건과
잘림·변조·도구 블록·용량 초과·타임아웃 등의 의도한 실패 14건이다.

| 합성 재생 지표 | 분자/분모 | 범위 |
| --- | --- | --- |
| 최종 계약 준수 | 24/24 | 실패 시 원본 포함 |
| 정상 표본 보강 | 10/10 | 실제 모델 호출 아님 |
| 의도한 실패 격리 | 14/14 | 동일 원본 반환 |
| 보호 필드 보존 | 24/24 | 모든 보호 필드 비교 |
| 선언한 근거 assertion | 85/85 | 부분 문자열·표본 수 |
| 정답 전문 또는 원본 일치 | 24/24 | 사전 기대값 대조 |
| 2~3문장 단락 | 30/30 | 정상 10건 × 3단락 |

합성 평가와 실제 AWS 두 사건은 별도 분모다. 허위 계정명·한 문장 단락을 주입하면
형식 파서가 수용해도 별도 근거·문장 평가가 실패하는 음성 회귀를 포함한다.
파서 자체가 자연어 사실성·문장 수를 보장한다고 주장하지 않는다.

```powershell
$env:PYTHONPATH = "src"
uv run python docs/roles/security/evaluate_p5_3.py `
  docs/roles/security/evidence/p5-3-2026-10-30/golden-set.json `
  docs/roles/security/evidence/p5-3-2026-10-30/offline-metrics.json
```

정적 main 대비 프롬프트 바이트는 SSH 10459→9889, Web 10535→9965로 각 570바이트 줄었다.
[prompt-comparison.json](evidence/p5-3-2026-10-30/prompt-comparison.json)에 기록하며 이를
토큰·비용·운영 성공률 감소량으로 환산하지 않는다. 출력 요구는 10필드→2필드이며 앱 병합 후
최종 계약은 전체 필드를 유지한다.
