## 1. 담당 도메인 개요 및 보안 R&R

보안 도메인은 CloudShield 파이프라인의 핵심인 **침해 위협 시그니처 룰 엔진, MITRE ATT&CK TTP 매핑, 결정론적 IncidentReport 생성 매퍼, 사후 비동기 Bedrock LLM 분석 파이프라인, 프롬프트 인젝션 방어 및 Fallback 복원력 검증**을 전담했습니다.

운영자의 수동 개입 없이도 정규식을 통해 $O(n)$ 선형 시간 복잡도로 침해 징후를 즉시 식별하고, 실시간 차단 경로와 사후 심층 분석 경로를 분리하여 차단 골든타임을 확보했습니다.

## 2. 핵심 엔지니어링 딥다이브 (위협 모델링 & 방어 메커니즘)

### 2.1 정규식 시그니처 엔진의 ReDoS(Catastrophic Backtracking) 방어
* **위협 모델 및 문제 정의**:
  - 로그 인입 시 악의적인 공격자가 정규식 취약점을 노려 지수적 역추적을 유발하는 문자열을 주입할 경우, 서버리스 Lambda의 CPU가 포화되고 타임아웃이 발생하여 전체 관제 파이프라인이 마비되는 ReDoS 위험이 존재했습니다.
* **알고리즘적 해결책**:
  - 중첩 반복 수량자(`(a+)+`, `([a-zA-Z0-9]+)*`) 등 Catastrophic Backtracking을 유발하는 패턴을 전면 배제했습니다.
  - Syslog 및 Nginx Combined 로그 형식에 맞춘 원자적 그룹화와 토큰 경계 검사를 적용하여 $O(n)$ 선형 시간 복잡도를 보장하는 정규식 엔진(`rules.py`)을 구축했습니다.
  - SSH Brute Force(`Failed password`) 및 Web 비인가 디렉터리 스캔 패턴에 대해 대규모 합성 로그 주입 시에도 지연 없이 안정적으로 파싱을 완료했습니다.

### 2.2 10초 실시간 경로와 사후 비동기 LLM 파이프라인 분리
* **아키텍처적 결단**:
  - 외부 Bedrock LLM API는 토큰 생성 및 네트워크 RTT로 인해 수 초의 레이턴시가 발생합니다.
  - 이를 실시간 차단 경로에 동기 결합할 경우 10초 SLA 골든타임을 놓치게 되는 문제가 있었습니다.
* **경로 분리 구조 및 역할 정의**:
  - **1차 실시간 차단 경로 (정형 요약)**: 외부 API 호출이 전혀 없는 순수 로컬 결정론적 매퍼(incident_mapper.py)를 통해 침해 팩트를 1ms 내에 (1) 정형 매핑하고 L4/L7 원자적 차단을 즉각 트리거했습니다.
  - **2차 사후 분석 경로 (비정형 추론)**: 단순 정형 보고서 생성을 넘어 비인가 웹 요청 URI에 난독화된 악성 페이로드의 공격 의도 파악과 3대 권고 조치 추론이라는 비정형 인텔리전스 영역을 처리하기 위해 EventBridge 비동기 LLM 워커(llm_worker.py)로 격리 배치했습니다.

### 2.3 상사 보고용 3단 구조화 양식 프롬프트 엔지니어링
* **사실 기반 엄격 양식**:
  - 보안 담당자와 경영진 간의 신속한 의사결정을 돕기 위해 보고서 형식을 표준화했습니다:
    - `[1. 침해 개요]`: 관측된 공격 행위의 핵심 요약 (400자 이하)
    - `[2. 관측 로그 근거]`: 실제 확인된 시각·계정·URI·상태 코드 팩트 (400자 이하)
    - `[3. 영향도 및 침해 판정]`: 관측 사실과 미확인 사실을 구분한 객관적 판정 (400자 이하)
    - 3대 권고: `[즉시 조치]`, `[설정 점검]`, `[재발 방지]` 순서 강제
* **미확인 사실 단정 방지**:
  - HTTP 403을 WAF 집행으로 단정하지 않고 HTTP 200을 정보 유출로 비약하지 않도록 프롬프트 가드레일을 설계했습니다.

### 2.4 프롬프트 인젝션 방어 및 Bedrock 장애 회귀 검증
* **보호 필드 불변성 검증**:
  - 공격자가 SSH 계정명이나 Web URL에 악의적인 프롬프트 탈옥 구문(`Ignore previous instructions`)을 삽입하더라도, 파서 단계에서 `incident_id`, `source_ip`, `remediation_action`, `mitre_attack` 등 핵심 보안 메타데이터 변조를 엄격히 방어했습니다.
* **비표시 제어문자(`\uXXXX`) 가시화 방어**:
  - 입력 로그에 포함된 C0/C1 비표시 제어문자를 가시화 표기로 변환하여 감사 추적 무결성을 유지하고 프롬프트 혼선을 방어했습니다.
* **Fallback 고정 평가셋 15건 회귀 검증**:
  - Bedrock API 타임아웃, 중단 응답, 형식 위반 발생 시에도 예외를 전파하지 않고 원본 IncidentReport를 안전하게 보존하는 15건의 오프라인 골든셋 회귀 테스트를 구축했습니다.
