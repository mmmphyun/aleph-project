# P3-3A 타깃 SSH 모의 공격 계정

- 관련 이슈: #173
- 대상: 승인된 Ubuntu 타깃 EC2의 `init_target_server.sh`
- 계정: 네트워크 러너 기본 규격과 동일한 `cloudshield_test`

## 구성 원리

신규 계정은 일반 UID와 전용 그룹으로 생성한다. 무작위 비밀번호를 SHA-512 crypt 해시로 저장하고 평문은 출력·파일 저장하지 않는다. 실패 로그인 실증용이므로 알려진 성공 로그인 비밀번호를 제공하지 않는다. 재실행 시 기존 계정의 비밀번호를 변경하지 않으며 특권 그룹 또는 잠긴 계정은 오류로 중단한다. 별도 sudoers 직접 부여 등 수동 권한 변경은 실습 전에 운영자가 점검한다.

전역 패스워드·키보드 대화형 인증을 끄고 공개키 인증을 유지한다. 파일 끝의 관리 Match 블록에서 실습 계정만 password 인증을 허용하며 포워딩과 TTY를 제한한다. 실습 계정 이름에 접미사가 필요한 경우 자동 지원하지 않으므로 기본 계정을 사용한다.

`sshd -t`와 `sshd -T -C`로 실습 계정 및 ubuntu를 포함한 모든 로컬 계정 정책을 검증한다. 기존 관리 블록 외 Match 또는 표준 drop-in 경로 외 Include가 있으면 임의로 덮어쓰지 않고 설정을 복원한 뒤 중단한다. 이 보수적 정책은 인증을 허용하지 않는 기존 Match도 거부하므로 운영자가 별도 정책을 검토해야 한다. 구문 오류, 정책 불일치, 명령 실패는 초기화를 실패시키고 SSH 설정을 복원한다. 명령 치환에서 ERR 트랩이 중복 실행되어도 복원 파일을 삭제하지 않는다. 서비스 재시작 실패 시 복원 설정으로 재기동하고 복구 실패를 명시적으로 알린다. 계정 생성 후 후속 단계가 실패하면 일반 계정은 남을 수 있으나 재실행에서 재사용된다.

## 운영 검증

이 PR은 AWS에 배포하지 않는다. 운영자는 관리자 키 접속을 확보하고 승인된 Kali 출발지만 허용하는 SG를 확인한 뒤 초기화를 실행한다. SG 변경과 공격 러너 수정은 이번 범위에 포함하지 않는다. 기존 사용자에게 패스워드 인증이 필요했던 타깃에는 정책 변경 영향을 먼저 확인한다.

1. 타깃에서 `sudo passwd -S cloudshield_test`와 `id cloudshield_test`를 확인한다.
2. `sudo sshd -T -C user=cloudshield_test,host=localhost,addr=127.0.0.1`에서 password 인증과 포워딩 제한을 확인한다. 실제 출발지 조건을 쓰는 기존 Match가 있으면 해당 주소로도 검증한다.
3. 승인된 출발지에서 잘못된 비밀번호로 단일 로그인을 시도하고 `/var/log/auth.log`에 `Failed password for cloudshield_test from ...`가 기록되는지 확인한다.
4. `/cloudshield/target/auth-log` 수집과 관리자 공개키 접속을 확인한다. 실패 로그인에는 랜덤 비밀번호를 알 필요가 없다.

## 로컬 검증 범위

실제 스크립트 구간을 Bash로 실행하고 시스템 명령을 대체해 신규/기존 계정, 비밀번호 설정 실패 정리, 특권 그룹·잠금 거부, SSH 정책 오류 및 재실행을 검증한다. 실제 Ubuntu sshd, PAM, EC2와 CloudWatch의 동작은 배포 후 위 운영 검증이 필요하다.
