## 화면 검증의 제한

Docker daemon에 연결 가능하지만 기존 Grafana 컨테이너·localhost:3000 서비스는 없었다.
프로젝트 지정 `grafana/grafana-oss:11.2.0` 이미지 다운로드를 완료했다.
기존 프로비저닝·B 대시보드·호스트 AWS 프로필을 읽기 전용 마운트한 임시 컨테이너로
화면 검증을 준비했으나 자동 승인 심사가 실행을 거부했다.
거부 사유는 AWS 자격증명 디렉토리를 컨테이너에 노출하고 익명 접근을 활성화하는 위험이다.
검증 컨테이너는 생성되지 않았다. 재시도 또는 우회하지 않았다.

따라서 완료 범위는 **4개 패널의 실제 AWS 쿼리·지표 대조**다.
Grafana 데이터소스 경유 실행·파이 차트/표의 화면 렌더링은 아직 미검증이다.
화면 검증을 이어가려면 인증이 활성화된 Grafana 환경에 대한 승인된 AWS 조회 연결이 필요하다.

증거: `evidence/p5-2-2026-10-30/logs-insights-results.json`,
`evidence/p5-2-2026-10-30/validation-summary.json`.
계정 ID와 로그 포인터는 저장 증거에서 제거했다. AWS 자격증명·토큰을 파일로 복사하지 않았다.
이번 변경은 문서·증거 파일뿐이며 제품 코드·계약·인프라·테스트는 변경하지 않았다.
JSON 파싱·5개 쿼리 Complete·수치 대조 및 `git diff --check`를 확인했다.

## 승인 후 Grafana 화면 검증 완료

사용자가 AWS 프로필 연결과 익명 접근 비활성화를 명시적으로 승인한 뒤 수행했다.
`cloudshield-p5-2-validation` 임시 컨테이너를 127.0.0.1:3000에만 바인딩하고
`GF_AUTH_ANONYMOUS_ENABLED=false`로 설정했다. 호스트 AWS 설정은 읽기 전용 마운트,
`AWS_PROFILE=cloudshield-cloud-b`로 연결했다. 인증 없는 대시보드 API는 HTTP 401로 차단됨을 확인했다.
기존 프로비저닝·B 대시보드 파일은 읽기 전용으로 사용했고 infra 파일은 수정하지 않았다.

브라우저에서 임시 관리자 계정으로 로그인하고
`/d/cloudshield-p5-2/cloudshield-p5-2-secops`의 4개 패널을 직접 확인했다.
기본 viewport에서 상단 그래프와 하단 파이 차트·타임라인을 각각 스크롤해 확인했다.

- 인입 패널: 미관측 표시, 쿼리 오류 없음.
- 대응 시간: max/p95 그래프의 집계점 표시, Grafana 데이터소스 API 수치 모두 2.7042초.
- LLM: enhanced 파이 차트 100% 표시, 분모는 선택 구간의 관측 사건 1건.
- 타임라인: 8행 및 한글 메시지 정상 표시. 사건 ID 누락 행은 미관측으로 표시.
- Grafana `/api/ds/query`의 5개 refId `1A`, `1B`, `2A`, `3A`, `4A` 모두 status=200, 오류 없음.

화면 확인 범위는 10:16:00~10:17:00 KST로 설정했다.
`bin(1m)` 집계 시각은 10:16:00이므로, 10:16:20부터 조회하면 그래프 집계점이
축 밖으로 빠질 수 있다. 분 단위 집계 대조 시에는 분 경계를 포함해야 한다.
이 조건은 조회 범위 조정으로 해결했고 제품 코드·쿼리 변경은 없었다.

Grafana 경유 응답은 `evidence/p5-2-2026-10-30/grafana-datasource-results.json`에
계정 ID를 마스킹해 보존했다. 인증 헤더·임시 비밀번호·AWS 자격증명은 저장 증거에 포함하지 않았다.
검증 후 임시 컨테이너와 임시 관리자 비밀번호 파일을 정리했다.

이번 판정은 고정 로그 기반 실환경 통합 실증의 패널 표시 확인이다.
실제 공격 트래픽 실측·전체 공격 시작 기준 10초 SLA 검증으로 확대하지 않는다.
