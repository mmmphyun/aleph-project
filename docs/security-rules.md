# 보안 및 테스트 안전 규칙

## 자격증명과 비밀정보

다음 정보는 저장소에 올리지 않습니다.

- AWS Access Key와 Secret Key
- API Key
- 비밀번호와 OTP
- Slack·Discord Webhook URL
- 개인 키와 인증서
- 실제 사용자 데이터

로컬 비밀정보는 `.env`나 AWS Profile을 사용하고, GitHub Actions에서 AWS 접근이 필요할 때는 장기 키 대신 OIDC 기반 IAM Role을 사용합니다.

## AWS 권한

- 최소권한 원칙을 적용합니다.
- 테스트 계정과 운영 계정을 분리합니다.
- 자동화 역할에는 필요한 API와 리소스만 허용합니다.
- 관리자 권한은 기본값으로 사용하지 않습니다.
- Terraform 변경 전 `plan` 결과를 확인합니다.
- 비용이 발생하는 리소스는 생성·삭제 책임자를 정합니다.

## 로그

- 로그에 자격증명이나 민감한 원문 데이터를 남기지 않습니다.
- 테스트 로그에는 더미 계정과 테스트 리소스만 사용합니다.
- 사건 처리 과정과 권한 변경 결과는 감사 목적으로 남깁니다.

## 레드팀 테스트

- 별도 테스트 AWS 계정에서만 수행합니다.
- S3에는 더미 데이터만 사용합니다.
- 데이터 삭제, 암호화 키 삭제, 서비스 중단 테스트를 하지 않습니다.
- 실제 외부 시스템이나 제3자의 주소를 공격 대상으로 삼지 않습니다.
- 테스트가 끝나면 권한·보안 그룹·리소스를 원복합니다.

## 자동 대응

LLM은 사건 요약과 대응 추천을 보조합니다. 권한 발급, 권한 회수, 세션 차단, 보안 그룹 변경과 같은 실제 조치는 결정적 규칙과 승인 게이트를 통과해야 합니다.

자동 대응에는 항상 다음을 준비합니다.

- 실행 전 영향 범위
- 실패 시 원복 방법
- 실행 결과 기록
- 오탐 시 수동 복구 방법
