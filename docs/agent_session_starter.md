# CloudShield: 에이전트 세션 스타터 및 협업 가이드 (Team Guide)

이 문서는 팀원(네트워크, 클라우드 B, 보안)이 로컬 코딩 에이전트(Cursor, Claude Code, Antigravity 등)와 함께 작업할 때, 에이전트가 프로젝트 울타리를 벗어나지 않고 표준 절차를 준수하도록 통제하는 **"세션 기동 템플릿"**입니다.

---

## 1. 1세션 1이슈 불변의 원칙

> [!IMPORTANT]
> **"1개 이슈 = 1개 브랜치 = 1개 에이전트 대화창"**
> - 하나의 대화창에서 여러 이슈를 연속해서 작업하지 마십시오 (컨텍스트 오염 및 무단 지분 침범 발생).
> - 작업이 끝나고 PR을 올렸다면, 해당 대화창을 닫고 **반드시 새 대화창**을 열어 다음 작업을 시작하십시오.
> - 다른 팀원의 PR을 리뷰할 때도 개발 대화창이 아닌 **"리뷰 전용 새 대화창"**을 열어 검토하십시오.

---

## 2. 작업 시작 시 복사해서 쓸 프롬프트 (Starter Prompt)

새 대화창을 열고, 아래 텍스트에서 `[ ]` 부분을 본인 상황에 맞게 수정한 뒤 에이전트에게 입력하십시오:

```text
너는 CloudShield 프로젝트의 팀원이야.
루트의 AGENTS.md 파일과 docs/project-memory.md를 먼저 읽고 본 프로젝트의 규칙을 확인해.

[작업 기본 정보]
- 내 담당 직무: [네트워크 / 클라우드 B / 보안 / 클라우드 A]
- 해결할 GitHub 이슈 번호: #[이슈번호]
- 연관된 노션 카드 링크: [노션URL]
- 이번 작업 목표: [예: auth.log 기반 1차 시그니처 룰 탐지 함수 구현]

[진행 규칙]
1. 코드를 작성하기 전에, 이번 작업의 핵심 기술적 원리와 개념을 나에게 먼저 쉽게 설명해줘.
2. 타 팀원의 고유 영역 및 src/contracts/ 파일은 절대 수정하지 마.
3. 설명이 끝나면, main 브랜치 기준으로 `feat/[직무]-[기능]` 브랜치를 생성해줘.
4. 작업이 끝나면 powershell .\scripts\check.ps1 로컬 검증을 통과시키고, AGENTS.md의 컨벤션에 맞춰 최소 단위로 커밋해줘.
5. 마지막으로 .github/pull_request_template.md 양식에 맞춰 PR 본문 초안을 작성해줘.
```

---

## 3. 작업 라이프사이클 4단계 요약

| 단계 | 팀원 및 에이전트 행동 | 비고 |
| :--- | :--- | :--- |
| **1단계: 진입** | 팀 노션 스프린트에서 본인 티켓 1개 확인 $\rightarrow$ 새 대화창 오픈 $\rightarrow$ 스타터 프롬프트 입력 | 개념 문답 및 원리 학습 |
| **2단계: 격리** | GitHub Issue 생성 $\rightarrow$ `feat/<직무>-<기능>` 브랜치 분기 | 작업 환경 격리 |
| **3단계: 구현** | 본인 디렉토리 내 최소 단위 작성 $\rightarrow$ `powershell .\scripts\check.ps1` 통과 $\rightarrow$ 단위 커밋 | 타 영역 수정 차단 |
| **4단계: 종료** | PR 생성 (원리 3줄 요약 필수 기재) $\rightarrow$ 노션 상태 자동 전이 확인 $\rightarrow$ **대화창 종료** | 세션 종료 |

---

## 4. 타인 PR 리뷰 전용 세션 가이드

다른 팀원이 PR 리뷰를 요청한 경우, 본인 개발 대화창을 절대 사용하지 말고 **새 대화창**에서 다음 프롬프트를 입력하십시오:

```text
CloudShield 프로젝트의 PR 리뷰를 진행하려고 해.
AGENTS.md를 확인하고, 아래 PR diff 내용을 검토해줘:
- PR 번호: #[PR번호]
- 검토 관점: 
  1. 타 팀원의 영역(src/contracts/ 등)을 무단 침범했는가?
  2. 왜(Why), 제약조건(Constraints) 기술 주석이 프로덕션급으로 작성되었는가?
  3. 테스트 코드가 동반 작성되었는가?
발견된 문제점이나 개선 제안을 존댓말로 정중하게 리뷰 코멘트 형태로 작성해줘.
```
