## 2. 안건 및 배경
- **배경**:
  - 초기 기획 문서 간 충돌 존재: 상위 개요(`docs/01_project_overview.md`)는 실시간 차단(룰)과 심층 분석(비동기 LLM)의 분리 모델을 제시했으나, 세부 워크플로우(`docs/05`, `docs/06`)는 Lambda 인라인 동기 호출로 기술되어 보안 구현과 명세 간 괴리 발생.
  - 10초 이내 원자적 차단(Critical Path) 경로에 외부 LLM API를 동기 호출할 경우, 지연시간(RTT/Decoding 최소 1~3초, 최대 수 초) 및 Rate Limit/장애로 인해 10초 관통 SLA 준수 불가.
- **주요 안건**:
  1. 실시간 차단 경로에서 외부 LLM API 배제 및 결정론적 매핑(1차 룰 $\rightarrow$ `incident_mapper` $\rightarrow$ `IncidentReport` 승격) 확정.
  2. LLM의 역할을 실시간 차단 루프 밖의 "사후 비동기 심층 분석/리포팅"으로 명확히 격리.
  3. 보안 담당자의 기존 구현(결정론적 Fallback 매핑)의 적합성 공식 인정.

---

## 3. 논의 내용 및 의결 사항

### 3.1 Critical Path(실시간 10초 차단) 경로 확정
- 흐름: `로그 수집 -> 1차 룰 검증(rules.py) -> IncidentReport 결정론적 승격(incident_mapper.py) -> L4 SG / L7 WAF 차단 -> Slack 알림`
- 원칙: 이 경로에는 외부 네트워크/LLM API 호출을 일절 포함하지 않고 100% 로컬 결정론적 코드로 완결하여 10초 관통 SLA를 절대 보장함.

### 3.2 Out-of-band(사후 LLM 심층 분석) 경로 확정
- 흐름: `차단 완료 이벤트 발행 -> EventBridge/SQS -> 비동기 워커 -> MITRE ATT&CK RAG & LLM -> 사후 종합 분석 보고서 및 재발 방지 가이드 발송`
- 원칙: 시스템 차단 가용성을 위협하지 않는 비동기 영역으로 LLM 및 RAG 지능형 분석 파이프라인을 분리 배치함.

### 3.3 보안 담당 작업 인정 및 문서 정합성 동기화
- 보안 팀원이 결정론적 매핑을 택한 것은 10초 관통 SLA를 위한 올바른 엔지니어링 판단임을 상호 확인하고 PR #58 보고서를 머지 완료함.
- 클라우드 A가 테크 리드 권한으로 `docs/05_security_workflow.md`와 `docs/06_integrated_pipeline.md`를 이원화 하이브리드 모델로 즉시 개정함.
- 모듈명 명확성을 위해 보안 담당자가 후속 이슈 #60(`refactor(security): llm_analyzer 모듈을 incident_mapper로 리네이밍`)을 진행하기로 합의함.
